## 四、算法描述

### 总体流程

```
开始
  │
  ▼
输入源代码
  │
  ▼
预处理阶段
  ├── 处理 #include 预包含指令（跳过）
  ├── 处理 #define 宏展开（记录宏定义）
  └── 跳过其他预处理指令
  │
  ▼
词法分析阶段（逐个字符扫描）
  │
  ├── 空白字符 → 跳过
  ├── 无效字符 → 过滤
  ├── 注释     → 跳过
  ├── 字符串   → 输出字符串常量
  ├── 字符常量 → 输出字符常量
  ├── 分隔符   → 一词一类输出
  ├── 数字     → 数值转换 → 输出常数
  ├── 字母     → 查关键字表
  │     ├── 匹配关键字 → 一词一类输出
  │     └── 不匹配     → 标识符 → 登记符号表
  └── 运算符   → 一词一类（多字符优先）
  │
  ▼
输出 (CLASS, VALUE) 二元式序列
  │
  ▼
输出符号表（变量名表 + 常数表）
  │
  ▼
结束
```

### 具体算法

#### 1. 关键字识别算法
```
1. 预先建立关键字集合 KEYWORDS
2. 识别到一个单词后，查询 KEYWORDS
3. 若匹配 → 以单词本身为 CLASS，VALUE 为空
4. 若不匹配 → CLASS = "IDENTIFIER"，登记变量名表，VALUE = 序号
```

#### 2. 常数识别算法
```
1. 遇到数字字符，开始收集
2. 判断是否为十六进制（0x/0X）
3. 判断是否为浮点数（含小数点或 e/E）
4. 整数 → 数值转换 → 存入常数表（二进制形式）
5. 输出 (CONSTANT, 序号)
```

#### 3. 符号表建立算法
```
变量名表：
  1. 每遇到一个新标识符，序号 +1
  2. 存放该标识符字符串（截断至4个字符）
  3. 若已经存在，复用序号

常数表：
  1. 每遇到一个新整数常数，序号 +1
  2. 存放该整数的二进制形式
  3. 若已经存在，复用序号
```

## 七、调试情况

### 1. 标识符截断问题

**问题：** 作业要求变量名表存放最多4个字符的标识符，而 `printf` 长度为6。

**解决：** 在登记变量名表时，对超过4个字符的标识符进行截断处理，只保留前4个字符。同时在界面中标注"已截断"提示。

### 2. 多字符运算符识别顺序

**问题：** 输入 `++` 时被错误识别为两个单独的 `+` 运算符。

**解决：** 采用"最长匹配"原则，先尝试匹配3字符运算符，再尝试2字符，最后匹配单字符，确保 `++`、`>=` 等多字符运算符被正确识别。

### 3. 十六进制常数处理

**问题：** `0x1A` 形式的十六进制常数需要特殊处理。

**解决：** 检测到 `0x` 或 `0X` 前缀后，进入十六进制数字收集分支，使用 `Integer.parseInt(numStr.substring(2), 16)` 进行数值转换。

### 4. 预处理指令过滤

**问题：** `#include` 和 `#define` 行不应进入词法分析，否则会产生大量未知符号。

**解决：** 在预处理阶段，将 `#` 开头的行全部过滤，记录预处理信息但不进入词法分析流程。

## 八、设计技巧及体会

### 设计技巧

1. **采用 HashMap 实现关键字表和符号表**
   - 关键字查找时间复杂度 O(1)
   - 符号表使用 LinkedHashMap 保持插入顺序，方便查看

2. **多字符运算符优先匹配**
   - 按长度从长到短依次匹配，避免将 `>=` 识别为 `>` 和 `=`

3. **预处理与词法分析分离**
   - 先进行预处理（宏展开、预包含处理），再对处理后的代码进行词法分析，模块职责清晰

4. **图形界面采用 Java Swing**
   - 使用 JSplitPane 左右分栏，左边输入右边输出
   - 输出部分使用 JTabbedPane 分三个 Tab（二元式/变量名表/常数表）

5. **过滤无效字符**
   - 对 ASCII 码小于32或大于126的非标准字符进行过滤，提高程序健壮性

### 设计体会

1. **词法分析是编译的第一步，也是最基础的一步。** 通过本次实验，我深入理解了如何将源代码的字符流转换为有意义的单词符号流。

2. **有限状态自动机的思想贯穿始终。** 标识符识别、数字识别、注释过滤都可以用状态图表示，程序实现也是状态图到代码的映射。

3. **预处理在编译器中的重要性。** 宏展开和头文件包含是 C 语言编译前的必要步骤，本次实验让我理解了预处理器的基本工作原理。

4. **符号表管理是后续语法分析和语义分析的基础。** 标识符和常数的登记、查找、存储方式直接影响了编译器的效率。

5. **错误处理和边界情况很重要。** 例如标识符长度限制、多字符运算符、十六进制数等，这些细节决定了程序是否健壮。
