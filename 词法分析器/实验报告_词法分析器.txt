四、算法描述
================================================================================

总体流程：

    开始
      │
      ▼
    输入源代码
      │
      ▼
    预处理阶段
      ├── 处理 #include（跳过，记录信息）
      ├── 处理 #define（跳过，记录宏定义）
      └── 跳过其他预处理指令
      │
      ▼
    词法分析阶段（逐个字符扫描）
      │
      ├── 空白字符 → 跳过
      ├── 无效字符 → 过滤剔除
      ├── 注释 // 或 /* */ → 跳过
      ├── 字符串 "..." → 输出字符串常量
      ├── 字符常量 '...' → 输出字符常量
      ├── 分隔符 {,},(,),;,, → 一词一类输出
      ├── 数字 → 数值转换 → 登记常数表 → 输出 (CONSTANT, 序号)
      ├── 字母/$/_ → 查关键字表
      │     ├── 匹配关键字 → 以单词本身为类别码输出
      │     └── 不匹配 → 标识符 → 登记变量名表 → 输出 (IDENTIFIER, 序号)
      └── 运算符 → 一词一类输出（多字符优先匹配）
      │
      ▼
    输出 (CLASS, VALUE) 二元式序列
      │
      ▼
    输出符号表（变量名表 + 常数表）
      │
      ▼
    结束


具体算法详述：

【算法1：关键字识别算法】

  Step 1：预先建立关键字集合 KEYWORDS（包含 Java/C 的50余个保留字）
  Step 2：从源代码中逐个读取字符，遇到字母/$/_ 时开始收集单词
  Step 3：收集完整单词后，查询 KEYWORDS 集合
  Step 4：若匹配 → 以单词符号本身为 CLASS，VALUE 为空
  Step 5：若不匹配 → CLASS = "IDENTIFIER"，将标识符登记到变量名表，
           VALUE = 变量名表中的序号


【算法2：常数识别算法】

  Step 1：遇到数字字符或小数点开头，开始收集数字序列
  Step 2：判断是否为十六进制（检测 "0x" 或 "0X" 前缀）
  Step 3：判断是否为浮点数（检测小数点或 e/E 科学计数法标志）
  Step 4：若为整数 → 进行数值转换（字符串→二进制整数）
  Step 5：将该整数存入常数表（存放二进制形式）
  Step 6：输出 (CONSTANT, 常数表序号)


【算法3：符号表建立算法】

  变量名表：
    Step 1：每遇到一个新标识符，序号从 1 开始递增
    Step 2：存放该标识符字符串（最大长度为4个字符，超出则截断）
    Step 3：若该标识符已在表中，则复用其序号

  常数表：
    Step 1：每遇到一个新整数常数，序号从 1 开始递增
    Step 2：存放该整数的二进制形式字符串
    Step 3：若该常数已在表中，则复用其序号


【算法4：预处理算法】

  Step 1：将源代码按行分割
  Step 2：若某行以 #include 开头 → 提取头文件名，记录信息，跳过该行
  Step 3：若某行以 #define 开头 → 提取宏名和宏值，记录信息，跳过该行
  Step 4：其他 # 开头的预处理指令 → 跳过
  Step 5：剩余行拼接成纯源代码，送入词法分析器

七、调试情况
================================================================================

【问题1：标识符截断处理】

  现象：作业要求变量名表中存放的标识符字符串最大长度为4个字符，
       而测试代码中的 printf 长度为6，超出限制。
  
  解决：在登记变量名表时增加判断，当标识符长度超过4时，
       只取其前4个字符存入符号表，并在界面中标注"已截断"提示。
       不影响二元式输出中的单词符号本身。

  结果：二元式输出中仍显示完整的 "printf"，
       变量名表中显示截断后的 "prin"。


【问题2：多字符运算符识别】

  现象：输入 "++" 时被错误识别为两个单独的 "+" 运算符，
       导致输出两个 (+, ) 而非一个 (++, )。

  解决：采用"最长匹配"原则，按以下优先级依次匹配：
       先尝试匹配3字符运算符（如 >>>），
       再尝试2字符运算符（如 ++, >=, ==），
       最后匹配1字符运算符（如 +, -, *）。
       确保最长的运算符被优先识别。

  结果："++" 正确输出为 (++, )，">=" 正确输出为 (>=, )。


【问题3：十六进制常数处理】

  现象：输入 "0x1A" 时，前面的 "0" 被识别为整数0，
       后面的 "x1A" 被识别为标识符，分割错误。

  解决：检测到 "0x" 或 "0X" 前缀后，进入十六进制数字收集分支，
       使用 Integer.parseInt(numStr.substring(2), 16) 进行数值转换。

  结果："0x1A" 被正确识别为整型常数，值为26。


【问题4：预处理指令过滤】

  现象：#include <stdio.h> 和 #define MAX 100 等预处理行
       进入词法分析器后，# 号被当作未知符号，产生大量错误输出。

  解决：在预处理阶段按行扫描，识别以 # 开头的行为预处理指令。
       #include 行提取头文件名后跳过，
       #define 行提取宏定义信息后跳过，
       其他 # 开头行同样跳过，不进入词法分析器。

  结果：预处理行被正确过滤，只记录信息不产生单词，词法分析只处理纯源代码。


================================================================================
八、设计技巧及体会
================================================================================

【设计技巧】

1. 采用 HashSet 实现关键字表
   关键字查找时间复杂度为 O(1)，远高于线性查找。
   预先建立50余个 Java/C 保留字，以备识别关键字时查询。

2. 多字符运算符优先匹配
   按字符串长度从长到短依次匹配，即3字符→2字符→1字符，
   有效避免了 >=, ++, == 等运算符被错误分割的问题。

3. 预处理与词法分析相分离
   先对源代码进行预处理（宏展开、预包含处理），
   再将处理后的纯代码送入词法分析器，模块职责清晰。

4. Java Swing 图形界面
   采用 JSplitPane 实现左右分栏布局，
   左侧为输入区，右侧为结果区；
   结果区使用 JTabbedPane 分为三个Tab页，
   分别展示二元式输出、变量名表、常数表。

5. 过滤无效字符和注释
   对 ASCII 码范围外的不可见字符进行过滤，
   单行注释 // 和多行注释 /* */ 均被跳过，
   提高了程序的健壮性和容错能力。


【设计体会】

1. 词法分析是整个编译过程的基础
   通过本次实验，我深入理解了如何将源代码的字符流
   逐一识别并转换为有意义的单词符号流（Token序列）。
   这是编译器工作的第一步，也是最直观的一步。

2. 有限状态自动机的思想贯穿始终
   标识符识别、数字识别、注释过滤等过程都可以用
   状态图（状态转换图）来描述和设计。
   程序实现本质上是将状态图映射为代码中的分支判断。

3. 理解了预处理在编译中的重要作用
   宏展开和头文件包含是 C/C++ 编译前的必要步骤。
   本次实验让我明白了预处理器的工作原理，
   以及为什么预处理需要独立于词法分析器运行。

4. 符号表管理的重要性
   标识符表和常数表的管理方式直接影响编译器的效率。
   使用哈希表可以实现 O(1) 级别的查找速度，
   而选择合适的数据结构存储符号信息也很关键。

5. 边界情况处理是程序健壮性的关键
   标识符长度限制、多字符运算符的歧义性、
   十六进制/科学计数法的特殊格式等，
   这些细节往往决定了程序是否真正可用。
